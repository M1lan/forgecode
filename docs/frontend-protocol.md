# Forge frontend protocol (NDJSON, v1)

The `--frontend=json` mode of the `forge` binary speaks a versioned line
protocol over stdin (client → forge) and stdout (forge → client). Each line
is one self-describing JSON object terminated by a single `\n`. The protocol
is the contract between the forge process and an embedding driver — for
example an Emacs `forge.el` major mode, a Neovim plugin, or a future Helix
adapter.

This document is the source of truth. Schema changes that break wire
compatibility bump the protocol version.

## Status

- **Version**: `v1`
- **Stability**: unstable while we iterate; `--frontend=json` requires
  `--unstable` to opt in. The flag will be lifted once the schema has
  stabilised in real-world editor integrations (target window: ~4 weeks
  after first usable Emacs client).
- **Source of types**: `crates/forge_main/src/frontend/protocol.rs`. The Rust
  types are the canonical definition; this document mirrors them.

## Invocation

```
forge --frontend=json --unstable
```

Auto-detection never picks `json`; it is always opt-in. The piped-stdin
slurp (used in TTY mode for `cat prompt.txt | forge`) is suppressed under
JSON mode so the protocol reader has live access to stdin.

## Channels

| Channel | Direction | Format |
|---|---|---|
| stdin | client → forge | one [`ClientEvent`](#client-events) JSON object per line |
| stdout | forge → client | one [`ServerEvent`](#server-events) JSON object per line |
| stderr | forge → tooling | tracing logs (unstructured); never part of the protocol |
| log file | forge → tooling | structured tracing output (`forge_tracker::init_tracing`) |

stderr is reserved for fatal protocol failures only (e.g. malformed boot
sequence). All recoverable errors are reported in-band as
[`ServerEvent::Error`](#error). Clients should treat any byte on stdout that
is not a complete `\n`-terminated JSON object as a protocol violation and
log loudly.

## Versioning

Every event carries a `"v"` integer field. Forge checks the version on
client events and rejects mismatched versions with an
[`ServerEvent::Error`](#error). Clients should likewise check the `v` on
server events and refuse to interpret events whose `v` is greater than the
client's known version.

Forward compatibility rules:

- **Unknown event `kind`** (either direction) must not crash the receiver.
  Forge replies with an `error` event; clients should drop unknown
  server events and surface a warning.
- **Unknown fields** within a known event are tolerated. Adding a new
  optional field is a non-breaking change.
- **Renaming** a field, removing a field, or changing a field's type is a
  **breaking change** and bumps the version.

## Identifiers

| Type | Generated by | Used in |
|---|---|---|
| `id` (request id) | client | every `ClientEvent`; echoed back on direct error responses |
| `turn_id` | server | every `ServerEvent` produced as part of a turn (`turn_start` … `turn_end`) |
| `sel_id` | server | `select` and the matching `select_response` |
| `tool_id` | server | `tool_call` and the matching `tool_result` |

Ids are opaque non-empty strings. Clients should pick `id` values that are
unique within their session (a monotonically increasing counter is fine).

## Client events

All client events are objects with at least `{"kind": "<name>", "v": 1, "id": "..."}`.

### `submit`

Submit a new user turn.

```json
{"kind":"submit","v":1,"id":"c1","text":"refactor foo to bar","attachments":[]}
```

Fields:

- `text` — user message text (raw markdown allowed).
- `attachments` — reserved for future use; must be an empty array in v1.

### `cancel`

Cancel an in-flight turn.

```json
{"kind":"cancel","v":1,"id":"c2","target":"t1"}
```

Fields:

- `target` — the `turn_id` from a prior `turn_start` event.

If the target turn has already ended, the cancel is a no-op (no error).

### `select_response`

Answer a selector prompt previously emitted by forge.

```json
{"kind":"select_response","v":1,"id":"c3","target":"sel-7","value":"yes"}
```

Fields:

- `target` — the `sel_id` from the originating `select` event.
- `value` — the chosen option. For multi-select, a comma-separated list.
  v2 may switch this to a JSON array; v1 callers must preserve the string
  form for forward compatibility.

### `set_buffer`

Pre-fill the next prompt's input buffer. Mirrors the `set_buffer` semantics
in the TTY and comint frontends.

```json
{"kind":"set_buffer","v":1,"id":"c4","text":"draft message"}
```

Forge replies (next prompt cycle) with a `status { level: "prefill" }`
event so the client can `(insert)` the text into its input area.

### `command`

Run a built-in slash/colon command (e.g. `new`, `exit`, `model`).

```json
{"kind":"command","v":1,"id":"c5","name":"exit","args":[]}
```

Fields:

- `name` — bare command name; the leading `/` or `:` is optional.
- `args` — optional positional arguments, joined by spaces server-side
  before being parsed by `ForgeCommandManager::parse`.

## Server events

All server events are objects with at least `{"kind": "<name>", "v": 1}`.

### `ready`

Emitted exactly once after startup, before any other server event. Carries
enough context for the client to seed its UI (mode-line, status bar).

```json
{"kind":"ready","v":1,"conversation_id":"…","agent":"forge","model":"claude-opus-4-7"}
```

### `turn_start`

Marks the start of an assistant turn. All `chunk`, `reasoning`,
`tool_call`, `tool_result`, `status`, `usage` events between this and the
matching `turn_end` belong to the same turn.

```json
{"kind":"turn_start","v":1,"turn_id":"t1"}
```

### `chunk`

A streamed text chunk produced by the assistant. Append to a per-turn,
per-stream buffer.

```json
{"kind":"chunk","v":1,"turn_id":"t1","stream":"assistant","text":"Looking at "}
```

Fields:

- `stream` — channel name. `"assistant"` for the visible response;
  `"reasoning"` for chain-of-thought when the model emits it.
- `text` — raw text. May contain partial UTF-8 sequences across chunk
  boundaries; the wire format normalises them but clients should buffer
  before rendering markdown.

### `reasoning`

Optional convenience event for clients that want to display reasoning
separately from the response. Equivalent to `chunk` with
`stream: "reasoning"`.

### `tool_call`

Tool invocation announced by the assistant. The result arrives later as
`tool_result` with the same `tool_id`.

```json
{"kind":"tool_call","v":1,"turn_id":"t1","tool_id":"k1","name":"read","args":{"path":"foo.rs"}}
```

`args` is a free-form JSON value so clients can render per-tool views
(file paths as buttons, code blocks, diffs).

### `tool_result`

Result of a tool invocation.

```json
{"kind":"tool_result","v":1,"turn_id":"t1","tool_id":"k1","ok":true,"summary":"42 lines"}
```

Fields:

- `ok` — `true` if the tool succeeded.
- `summary` — short human-readable summary suitable for a one-line preview.

### `select`

Selector prompt.

```json
{"kind":"select","v":1,"sel_id":"sel-7","prompt":"Apply patch?","options":["yes","no","diff"]}
```

Fields:

- `multi` — optional, default `false`. `true` → multi-select.
- `default` — optional default value the user can confirm with empty input.

The client must reply with `select_response` carrying the same `sel_id`.

### `status`

Out-of-band status / progress event. Replaces the spinner under JSON mode.

```json
{"kind":"status","v":1,"level":"info","text":"streaming"}
```

`level` is one of `"info"`, `"warn"`, `"error"`. The reserved level
`"prefill"` is used by `set_buffer` round-trips and carries the prefill
text in `text`.

### `usage`

Token usage / cost accounting for the current turn. Emitted at turn end
and optionally on token-count changes during streaming. Clients should
treat the latest value as authoritative.

```json
{"kind":"usage","v":1,"turn_id":"t1","input_tokens":12345,"output_tokens":678,"cost":0.04}
```

### `turn_end`

Marks the end of an assistant turn. After this event, the next turn
begins with a fresh `turn_start`.

```json
{"kind":"turn_end","v":1,"turn_id":"t1"}
```

### `error`

Recoverable error tied either to a specific client request (echo `id`) or
to the session at large (omit `id`).

```json
{"kind":"error","v":1,"id":"c1","text":"bad request","cause":""}
```

Fields:

- `id` — optional. Present when the error was triggered by a specific
  client event.
- `text` — short human-readable summary.
- `cause` — optional debug / full-error chain. May be empty.

## Reference event sequence

A minimal end-to-end turn:

```
forge>  {"kind":"ready","v":1,"conversation_id":"abcd","agent":"forge","model":"claude-opus-4-7"}
client> {"kind":"submit","v":1,"id":"c1","text":"hi","attachments":[]}
forge>  {"kind":"turn_start","v":1,"turn_id":"t1"}
forge>  {"kind":"chunk","v":1,"turn_id":"t1","stream":"assistant","text":"Hello! "}
forge>  {"kind":"chunk","v":1,"turn_id":"t1","stream":"assistant","text":"How can I help?"}
forge>  {"kind":"usage","v":1,"turn_id":"t1","input_tokens":12,"output_tokens":7,"cost":0.0001}
forge>  {"kind":"turn_end","v":1,"turn_id":"t1"}
client> {"kind":"command","v":1,"id":"c2","name":"exit"}
```

The client closes stdin (or sends `command:exit`) to terminate the session
cleanly.

## Roadmap (post-v1)

- **Tool call streaming**: today `tool_call` arrives as a single object;
  v2 may stream large argument payloads.
- **Cancel ack**: explicit `cancel_ack` event to confirm cancellation,
  replacing the current "next chunk after cancel is the last" convention.
- **Multi-select arrays**: switch `select_response.value` from
  comma-separated string to JSON array.
- **Length-prefixed framing**: if NDJSON proves insufficient under heavy
  tool result load, switch to a length-prefixed framed protocol on the
  same channels.
